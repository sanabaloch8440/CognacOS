# Windows 11 x64 NTDLL export comparison

## Pinned reference

- Reference source: [WinExports ntdll.dll data](https://github.com/learn-more/winexports/tree/master/data/exports/nt100_x64_26200/ntdll.dll.json) and [human-readable table](https://winexports.info/dlls/ntdll_dll/).
- Export dataset: Windows 11 x64 25H2 data directory `nt100_x64_26200`; the PE metadata in this dataset reports file version `10.0.26100.7920` (AMD64).
- The committed inventory contains **2,516 named exports**. The source also includes an ordinal-only slot; named exports and total export-address-table entries are not identical.
- CognacOS's hand-maintained `ntdll/exports/ntdll-x64.def` is the active native PE export definition and is not the full reference list.

## In-tree inventory and stub policy

`ntdll/exports/windows-11-x64-exports.txt` is checked into the repository. It is the source input for the Rust NTDLL build and does not need to be downloaded, scraped, or generated by a GitHub Actions workflow. It contains one named export per line, plus comments identifying the pinned reference. The optional refresh helper is a maintenance tool only.

The Rust build script reads this committed inventory and unions it with names from `root/wine/dlls/ntdll/ntdll.spec` as a compatibility superset. For names that do not already have a Rust declaration, it emits a generic `STATUS_NOT_IMPLEMENTED` placeholder so a linker/import resolver can find the symbol by name.

## Important limitations

- The inventory is an export-name list, **not** a signature/ABI database. A zero-argument placeholder returning `STATUS_NOT_IMPLEMENTED` is only a name-level scaffold; it is not a safe implementation of the real function's signature or behavior.
- The Rust crate is currently an `rlib`; its symbols are not yet linked as a complete production PE32+ `ntdll.dll`.
- Ordinals, ordinal-only slots, forwarded exports, data exports, and exact signatures must be validated against the pinned Windows PE export directory before claiming binary-level compatibility.
- Replace placeholders with signature-correct implementations and tests as each native service is implemented.
