# Building CognacOS

CognacOS uses one pinned Rust compiler for all first-party source and one
LLVM LLD linker for every target. The same LLD executable is used in ELF,
UEFI/COFF, and PE/COFF modes. Target-specific driver aliases do not select
different linker implementations.

## Prerequisites

- Rust 1.88.0 with the targets listed in `rust-toolchain.toml`
- LLVM LLD, Clang's linker-driver frontend, `llvm-ar`, and `llvm-readobj`
- MinGW-w64 headers/import libraries and compiler-runtime archives for the
  Windows GNU target only; the GCC driver is not selected or invoked
- QEMU and OVMF for boot tests

Clang is used only as a linker driver with `-fuse-ld=lld`; it is not used to
compile project source. The bcrypt implementation uses RustCrypto primitives
and does not build a native C crypto library. No GCC, GNU ld, or proprietary
Microsoft linker is selected.

## Quick start

```sh
# Install the pinned Rust targets and verify the selected toolchain.
./scripts/build.sh setup

# Compile the core kernel, UEFI loader, ABI and driver libraries.
./scripts/build.sh check

# Build the release kernel PE32+ image and check the UEFI loader.
./scripts/build.sh build

# Run host-side ABI, crypto, driver and Rust tooling tests.
./scripts/build.sh test

# Format all Rust packages, verify formatting, and run strict Clippy checks.
./scripts/build.sh format
./scripts/build.sh fmt-check
./scripts/build.sh lint

# Run compile checks followed by host tests.
./scripts/build.sh all
```

Set `CARGO_TARGET_DIR` to move build products outside the repository. The
default is `target/`. Generated PE images, PDBs, serial logs and QEMU artifacts
are written under `build/` by the CI workflow.

## Target/linker policy

| Target | Source compiler | Linker |
|---|---|---|
| `x86_64-unknown-linux-gnu` | rustc | LLVM LLD via Clang driver |
| `x86_64-unknown-none` | rustc | LLVM LLD ELF mode |
| `x86_64-unknown-uefi` | rustc | LLVM LLD COFF/EFI mode |
| `x86_64-pc-windows-msvc` | rustc | LLVM LLD `lld-link` mode |
| `x86_64-pc-windows-gnu` | rustc | LLVM LLD GNU COFF mode via Clang driver |

The `lld-link`, `ld.lld`, and `rust-lld` names in the build environment are
aliases to the Rust toolchain's bundled LLD executable, not separate linkers.
The freestanding kernel and drivers retain their linker scripts, fixed-address
contracts, and debug information. Kernel ELF files remain available for DWARF
and GDB source-level debugging; PE32+ images are generated by the Rust
`cognacos-tools` converter.

## CI and release expectations

- Run `./scripts/build.sh toolchain` before diagnosing build failures.
- Keep export manifests and `.def` files under version control; they define
  ABI compatibility and must not be regenerated from build output.
- Preserve debug information and frame pointers in debug artifacts.
- Do not treat a successful compile as a successful boot. QEMU smoke tests and
  serial/GDB checks remain separate CI gates.
- Avoid ad-hoc compiler or linker overrides in workflow steps. Extend
  `.cargo/config.toml` and `scripts/build.sh` so local and CI builds share
  the same policy.
