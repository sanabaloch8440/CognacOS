# Building CognacOS

CognacOS uses a single, pinned Rust toolchain for first-party code and LLVM
LLD as its only linker. The same LLD binary is invoked in ELF, UEFI/COFF, and
PE/COFF modes; the target selects the required object format and ABI.

## Prerequisites

- Rust 1.88.0 with the targets listed in `rust-toolchain.toml`
- LLVM/Clang  (Clang is used only by native C dependencies such as AWS-LC;
  first-party OS and tooling sources are compiled with `rustc`)
- LLVM LLD, `llvm-ar`, `llvm-readobj`
- CMake, NASM, and Perl for the AWS-LC dependency build
- QEMU and OVMF for boot tests

The CI workflow installs the same pinned Rust toolchain and LLVM packages.
GCC/MinGW and Microsoft's proprietary linker are not selected by the project
build. Do not set target-specific linker overrides outside `.cargo/config.toml`
or `scripts/build.sh`.

## Quick start

```sh
# Install the pinned Rust targets and verify the selected toolchain.
./scripts/build.sh setup

# Compile the core kernel, UEFI loader, ABI and driver libraries.
./scripts/build.sh check

# Run host-side ABI, crypto, driver and Rust tooling tests.
./scripts/build.sh test

# Run both compile checks and host tests.
./scripts/build.sh all
```

Set `CARGO_TARGET_DIR` to move build products outside the repository. The
default is `target/`. Generated PE images, PDBs, serial logs and QEMU artifacts
are written under `build/` by the CI workflow.

## Target/linker policy

| Target | Compiler | Linker |
|---|---|---|
| `x86_64-unknown-linux-gnu` | rustc (Clang for C dependencies) | LLVM LLD via Clang driver |
| `x86_64-unknown-none` | rustc | LLVM LLD ELF mode |
| `x86_64-unknown-uefi` | rustc | LLVM LLD COFF/EFI mode |
| `x86_64-pc-windows-msvc` | rustc | LLVM LLD `lld-link` mode |\n| `x86_64-pc-windows-gnu` | rustc (Clang for AWS-LC C sources) | LLVM LLD GNU COFF mode |

The `lld-link` and `rust-lld` names in the build environment are aliases to
the Rust toolchain's bundled LLD executable, not separate linkers. The
freestanding kernel and drivers retain their linker scripts, fixed-address
contracts, and debug information. Kernel ELF files remain available for DWARF
and GDB source-level debugging; PE32+ images are generated by the Rust
`cognacos-tools` converter.

## CI and release expectations

- Run `./scripts/build.sh toolchain` before diagnosing build failures.
- Keep export manifests and `.def` files under version control; they define
  ABI compatibility and must not be regenerated from the build output.
- Preserve debug information and frame pointers in debug artifacts.
- Do not treat a successful compile as a successful boot. QEMU smoke tests and
  serial/GDB checks remain separate CI gates.
- Avoid adding ad-hoc compiler or linker commands to workflow steps. Extend
  `.cargo/config.toml` and `scripts/build.sh` so local and CI builds share
  the same policy.
