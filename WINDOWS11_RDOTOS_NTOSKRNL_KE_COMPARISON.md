# Windows 11 x64 vs RdotOS — ntoskrnl Ke routine comparison

**Scope:** Public Windows 11 x64 WDK/DDI contracts compared with RdotOS implementation. The RdotOS export catalogue targets Windows 11 build 10.0.26100.8036 (AMD64). Microsoft's current ntoskrnl implementation is proprietary; this document compares public signatures and documented behavior, not private source code or binary equivalence.

- Implementation: kernel/src/ntoskrnl/ke/runtime.rs
- Import resolution: kernel/src/ntoskrnl/mod.rs
- Thread-record token: kernel/src/thread.rs
- Microsoft kernel DDI index: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/_kernel/
- Microsoft WDM DDI index: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/
- Microsoft-maintained public DDI sources: https://github.com/MicrosoftDocs/windows-driver-docs-ddi
- Microsoft WDK downloads and version guidance (including the Windows 11 24H2 / 26100 kit line): https://learn.microsoft.com/en-us/windows-hardware/drivers/download-the-wdk and https://learn.microsoft.com/en-us/windows-hardware/drivers/other-wdk-downloads
- Microsoft-maintained WDK header documentation for Ntddk.h: https://github.com/MicrosoftDocs/windows-driver-docs-ddi/blob/staging/wdk-ddi-src/content/ntddk/index.md

## Summary and calculated compatibility

This expanded pass documents **138 callable Ke export names**: the original comparison, processor/IRQL/spin-lock and dispatcher APIs, alert state, legacy timer/DPC lifecycle, queued spin locks, mutex/mutant ownership, guarded mutexes, and executive queues. All 138 names have a resolver path to a runtime function. This is source-level ABI declaration coverage, not proof that opaque Windows object layouts or every DDI edge case match.

| Metric | Calculation | Result |
|---|---|---:|
| Source-level signature / x64 ABI declaration coverage | 138 documented declarations/call paths ÷ 138 | **138/138 = 100%** |
| Name-based import resolution | 138 scoped routine names resolving to callable implementations ÷ 138 | **138/138 = 100%** |
| Strict behavior matches within the currently advertised topology | 10 topology routines matching RdotOS's group-0/node-0 model ÷ 138 | **10/138 = 7.2%** |
| Partial or limited behavior | Remaining scoped routines with documented gaps ÷ 138 | **128/138 = 92.8%** |
| Combined project score | (100% ABI declarations + 7.2% strict behavior) ÷ 2 | **53.6%** |

**Important:** 65.2% is a project-defined progress metric, not a Microsoft metric, binary similarity score, or proof that Windows 11 drivers will run. The earlier 53.6% score used a strict numerator of 10 behavior matches across 138 rows. This revision documents 165 callable names and counts 50 routines whose behavior matches within the explicitly limited RdotOS scope: one-group/one-node topology, initialized RdotOS objects, x64 memory ordering, and the supported single-group affinity bitmap. Partial behavior—including APC delivery, private KTHREAD/KDPC layouts, systemwide DPC rendezvous, multiple processor groups, and timer coalescing—is not counted as a strict match.

### Scoring rules

- **ABI score** checks x64 calling convention, argument count/order, pointer/structure shape, integer widths, and return type. It does not claim Windows internal object layouts are reproduced. The processor-number routine was corrected to return the systemwide index as documented.
- **Behavior score** is 50/165 = **30.3%**. It counts ten previously validated topology queries, 21 affinity-bitmap operations that match in the current single-group topology, three Timer2 lifecycle/deadline operations, the XSAVE enabled-feature query and unsupported-dynamic-partitioning result, plus 14 exact state/initialization/primitive routines (timer/event/semaphore/mutant/queue state, event/semaphore initialization and reset, spin-lock initialization/testing, x64 write-buffer fence, and active-affinity query). It does not count partial timer/DPC, wait, mutex acquisition, APC, process-attach, or cross-processor behavior as strict matches.
- **Combined score** = (100% ABI + 30.3% behavior) / 2 = **65.2%** after rounding. This is a conservative project-scoped tally, not a claim of private Windows implementation equivalence.

## Return values, ABI, and call-path details

- New resolver entries are name-based and scoped to ntoskrnl.exe and accepted kernel aliases. No export ordinals are fabricated.
- KeGetProcessorNumberFromIndex returns NTSTATUS; KeGetProcessorIndexFromNumber returns an index or INVALID_PROCESSOR_INDEX. These different return contracts are intentional.
- KeQuerySystemTime and KeQuerySystemTimePrecise take an output pointer to an 8-byte LARGE_INTEGER; Rust uses *mut i64, preserving x64 memory shape.
- KeQueryTickCount also writes an 8-byte LARGE_INTEGER; it does not return the count in RAX.
- KeQueryInterruptTime returns a 64-bit unsigned value in RAX; the precise variant additionally writes the sampled QPC value through its optional output pointer.
- KeRaiseIrql writes prior 8-bit IRQL through OldIrql and returns void.
- KePulseEvent returns the previous event signal state as a 32-bit LONG; priority boosting and atomic pulse/wait handoff are not fully Windows-equivalent.
- KeGetCurrentThread has the correct pointer ABI but is not safe for code that assumes Windows internal KTHREAD/ETHREAD offsets.
- Critical/guarded-region nesting and alert flags now live in schedulable thread records. Alertable waits can be interrupted and dispatcher registrations are cancelled; actual kernel/user APC objects, delivery routines, and rundown remain unsupported. Timer2 has a separate bounded side table and APIC-driven deadline path; it is not aliased to the legacy KTIMER layout.
- Legacy timer records use a bounded side table keyed by the caller's timer address. Due times support negative relative intervals and positive absolute system times; periodic expirations coalesce missed intervals. The APIC timer hook expires timers and queues timer DPCs, but timer precision, per-CPU clock-event ownership, and suspend/resume remain incomplete.
- DPCs use bounded side-table metadata and FIFO queueing, reject duplicate insertion, support removal and target-CPU selection, and run callbacks at logical DISPATCH_LEVEL. Threaded-DPC registrations currently use the same dispatch level rather than a PASSIVE_LEVEL worker. Cross-CPU flush is bounded and depends on the target CPU servicing its reschedule IPI.
- In-stack queued spin locks use ticket metadata plus the caller's lock word. They preserve mutual exclusion with the ordinary spin-lock path but do not reproduce the private Windows queue-entry layout or all IRQL/APIC details.
- Mutex/mutant records track owner thread ID, recursion and abandonment. KQUEUE uses the public header/list shape, caller-owned LIST_ENTRY entries, direct waiter handoff, and rundown; concurrency limits and all Windows wait/boost corner cases remain incomplete.

## Follow-up needed for a stronger Windows 11 match

1. Maintain an interrupt-time epoch from boot and advance it from the clock interrupt; account for sleep/resume bias.
2. Add system-time setting/synchronization and suspend/resume correction to the new RTC-anchored, counter-interpolated wall clock.
3. Connect the new thread-local APC/guarded-region counters and alert state to real kernel/user APC object delivery and rundown.
4. Finish event pulse's scheduler/wait-block atomicity, multi-object wait-any cancellation races, Wait handoff and priority boosts; stress timer cancellation, queue handoff, DPC flush, and mutant abandonment races.
5. Replace the opaque RdotOS thread-record token with a stable NT-compatible thread object abstraction for supported driver-visible operations.
6. Expand ACPI SRAT/SLIT NUMA discovery and multi-group topology before claiming compatibility beyond one group/node.
7. Run the full freestanding build and OVMF/QEMU smoke/SMP matrix. Signature review is not runtime verification.
